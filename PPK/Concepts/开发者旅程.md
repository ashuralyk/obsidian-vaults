# 开发者旅程

## 是什么

开发者旅程是从发现到规模化的理想路径：Discover、Evaluate、Learn、Build、Scale。每一段都有开发者自己的目标，以及必须回答的问题。触点分成 Internal（你能控制）与 External（你只能影响）。整张地图由 DevRel 负责，即使执行落在各个部门。

阶段标记的是意图变化，不是耗时长短。有人可能一天走完前几步，也有人一年都找不到用例。API 的旅程通常比 SDK 或 HDK 更短。老客户也可能直接进入 Build。

## 为何重要

多数有意义的结果，出现在进入 Scale 并且留下来之后。Awareness 再高，若在 Learn 阶段中断，转换率仍是零。减少摩擦本身就是竞争优势。

## 实践含义

- Discover 阶段要回答：这对我有用吗？
- Evaluate 阶段要回答：能满足需求吗？并在这里寻找红旗。
- Learn 阶段要回答：它怎么工作？必须过 [[Time to Hello World]]。
- Build 阶段要回答：能否做出概念验证或最小可行产品？此时仍未完全承诺。
- Scale 阶段要回答：能否长期用？看留存、路线图、成功与展示。

用摩擦记录、社区反馈和漏斗数据来验证旅程。讨论热度不是旅程指标。
