# 笔记范式

Agent 写库时必须遵守本页；Cursor 与 Obsidian Copilot 适用同一套规则。类型化链接必须同时出现在正文 `[[wikilink]]` 里，Graph 才能画出来。两边同时操作时，见 `AGENTS.md` 的「一致性」。

## 必填 YAML

| 字段 | 说明 |
| --- | --- |
| `type` | `inbox` \| `daily` \| `source` \| `concept` \| `moc` \| `area` \| `project` \| `output` |
| `status` | `seedling` \| `evergreen` \| `archived` |
| `updated` | `YYYY-MM-DD` |
| `aliases` | 列表，可空 |
| `tags` | 必须含 `#type/<type>`，供 Graph 着色 |

可选：`sources`（文献路径）、`url`、`authors`。多源互证的概念可另加 `#corroboration/multi-source`。

## 目录

| 路径 | type |
| --- | --- |
| `Inbox/` | 未晋升原料 |
| `Daily/` | `daily`，文件名 `YYYY-MM-DD.md` |
| `Sources/` | `source`（网页 / 书 / 论文摘录，不是理解本身） |
| `Concepts/` | `concept`（一笔记一概念） |
| `Maps/` | `moc` |
| `Areas/` | `area`（稳定领域） |
| `Projects/` | `project`（有期限） |
| `Outputs/briefings/` `Outputs/decisions/` | `output` |
| `Meta/templates/` | 模板，不是知识本体 |

## 多源互证（硬规则）

同一类别的知识会从不同时代、不同体裁的来源中反复出现。入库时必须保留这些角度，而不是因为库里已有“差不多”的概念就跳过落盘。

1. **禁止因相似而省略。** 后一本书讲到与既有概念相近的主张时，必须落盘：要么写入既有概念的「多源互证」并挂上新 `source`，要么在机制/视角确实不同时新建概念并与旧概念建立关系边。
2. **同机制、多角度，优先加深同一概念。** 底层机制相同，只是时代、案例或表述不同时，更新同一篇 `concept`，用「多源互证」分列各来源的角度，并在「链接 / 来源」中保留全部来源。这不是重复劳动；跨书互证提高该知识的参考价值。
3. **同主题、异机制，必须新建。** 主题相近但因果机制、适用范围或对立面不同时，新建原子概念，再用 `[[wikilink]]` 标明定义 / 依赖 / 对立关系。不要把不同机制硬塞进旧标题。
4. **多源出现是加分信号。** 被不同时代或不同类别来源共同指向的概念，更接近可迁移的稳定判断。入库后应显式写出互证关系，并可用 `#corroboration/multi-source` 标记，供检索与综合时优先采信。
5. **防重复的是同名空壳，不是新角度。** 搜索是为了避免无信息增量的第二篇同名笔记，不是为了拦截新来源的理解。没有新角度、只换措辞的内容才应合并省略。

## 允许的边

- `source` → `concept`
- `daily` → `concept` \| `area` \| `project`
- `concept` → `concept`（仅定义 / 依赖 / 对立等真正关系）
- `moc` → 成员
- `area` → 其下概念 / 项目
- `output` → 引用过的 `concept` / `source`

禁止：日记互链成网、来源之间无意义互链、把 Area 当全文 tag、为 Graph 好看乱连。

## 正文链接块

每篇在文末保留：

```markdown
## 链接
- [[目标笔记]]
```

按关系选用「来源 / 概念 / 领域 / 项目 / 成员 / 引用」等小标题，不要把未允许的边写进去。

概念若有多个来源，在「是什么 / 为何重要」之后增加：

```markdown
## 多源互证

- 来源A（年代）：……角度……
- 来源B（年代）：……角度……

互证要点：……
```

## 正文文笔与整理口吻（硬规则）

落盘正文、简报/决策，以及面向用户的整理、导读、复盘与问答，一律采用 mentor 口吻：像一位懂行的老师在把事情讲清楚，而不是在交报告、贴标签或堆要点。

要求：

1. **通畅易读。** 用完整句子，一段一事，逻辑清楚。列表里的每一项也要能单独读通，不要堆关键词。
2. **拒绝电报体。** 禁止残句、口号串、无主语的短语清单直接充当正文。
3. **拒绝 AI 感。** 少用空泛排比、万能过渡、套话开头和自我表扬式总结；不写“总而言之，我们可以得出如下结论”这类腔调。先给判断，再给理由。
4. **mentor，不是播报员。** 可以点出轻重、提醒误区、说明适用边界，但保持克制，不说教堆砌。
5. **写完默读。** 主谓残缺、搭配错误、标点混乱、中英语序缠杂，一律改掉再提交。

Cursor 见规则 `note-prose.mdc`；Copilot 写库与整理输出时同样遵守本节。
