# 风口期 DevRel 复盘

这是一份情境简报，不是领域里的普遍结论。这一次的触发是代币与板块轮动；普遍机制见文末引用的概念。

## 结论

失败发生在 [[开发者旅程]] 的 Learn 门闩。想来 Build 的人既没有像样的 demo，跟着文档也走不通，于是 Build 与 Scale 从未发生。根因更早：开发者供给没有被当成产品来养，高管也不重视 SDK，同时又用 Stage 0 或 Stage 1 的组织去接 Discover 洪峰（见 [[DevRel 项目成熟度]]）。轮动期间才组建的团队，是这个错位的结果，不是病因。

事后比热潮更静，是因为围观层散掉了，再加上「没出圈」这把错尺子改写了判断（见 [[DevRel 指标]]、[[社区不等于开发者项目]]）。只单向同步进展，恢复不了互惠。

纠偏方向是对的：打磨 SDK 与文档，就是在补 [[Developer Experience]]。还没吃完的课是：请不熟悉产品的人走一遍 [[Time to Hello World]] 来验收；针对明确画像来打磨；把承诺接到公司目标里；文档走通之后，再接上支持、变更日志与内圈。

「AI 友好」只应用来减少摩擦、预置用例和提供沙盒。如果把它当成「Learn 与 Build 会因此变简单」的前提，不过是 [[Build it and they will come]] 换了一层皮。

## 展开

1. 此前注意力放在核心产品上，氛围偏高傲：只要够先进，人就会自己爬过旅程。
2. 板块轮动把 Awareness 灌满了；SDK 尚未就绪，于是临时抱佛脚。
3. 社区在热潮过后更静；成功一度被定义成出圈和价格。
4. 现在主要精力放在 SDK、文档，以及让平台对 AI 更友好。书把 DX 当作中心，并不认为这些阶段会因为时代而消失。
