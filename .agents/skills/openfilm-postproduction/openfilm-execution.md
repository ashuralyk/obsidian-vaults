# OpenFilm 执行与技术核对

## 建立或接手时间线

技术入口以当前版本为准。执行 `npx -y openfilm@latest` 读取官方入口，按选定版本用 `skill film` 和各命令 `--help` 复核本节。已有桌面 Studio 工程应先确认实际会读写同一份工程文件，尊重用户锁定和正在编辑的内容。命令在正确的工程目录运行，先确认会取到目标 `film.html`。开始实剪前按官方流程打开目标工程的 Studio，让用户看到同一时间线；已有项目先核对文件再开。`open` 可能启动 Studio 或建立一个空工程，纯诊断可以用现有工程和 `look` 定位。技术出处见 [OpenFilm Agent manual](https://openfilm.dev/docs/manual/)、[CLI](https://openfilm.dev/docs/cli/) 和 [Spec](https://openfilm.dev/spec/)。

`film.html` 存的是时间线，`assets/` 里放项目所需的本地媒体，逐镜绘制的页面是独立 HTML。已有视频、静帧、声音直接作为片段使用。一个 `<section>` 是一条轨，轨内片段顺序排放且不重叠；需同时出现的画面或声音分别用不同轨。靠前的轨在画面上层。视频、图片、声音和代码镜头分别用 `<video>`、`<img>`、`<audio>`、`<iframe>`。在只修改一个镜头或 cue 时保留既有 ID、锁轨、用户的 `overrides` 以及和工作无关的布局。视频裁切先用已有布局与 CSS 检查输出画幅；调整时间用源区间和 `at`，有变速需求再用 `speed`。优先保持原媒体可重用。

开始时核对源文件存在、编码、实际片长、画面比例、旋转、帧率和音轨。如果代理、最终原件或 VFR 版本的事件位置不同，在同一锚点分别找时间。只在规范化、分离同期声或兼容性实际有需要时创建独立的派生素材，保留源文件与映射。项目迁移后用相对路径和实际播放验证链接。对外提供完整工程时核对没有只在本机某个目录或远端会话才能读取的素材。

## 区分源时间、片段时间和全片时间

- `src="assets/take.mp4#t=2,5"` 选中源片段从第 2 秒到第 5 秒的范围。 `at="3"` 将源片段开头放在全片第 3 秒。
- 以左闭右开的区间记录镜头。若变速为 `speed`，成片时长是 `(sourceOut - sourceIn) / speed`。源文件中发生于 `sourceEvent` 的事件，在成片时间是 `at + (sourceEvent - sourceIn) / speed`。多段动过时分别求，不把整片当成同一个恒定偏移。
- 帧率需要显式核对。用整数成片帧定位关键切口，并按已选帧率换算时值。以 24 fps 的第 72 帧为例，若编号从 0 起就是 3 秒。不要把 23.976 和 24、29.97 与 30 混用，也别把小数秒写成时间码的帧数。分数帧率的参数和实际成品是否吻合，要看当前 CLI 帮助及导出文件的帧率。
- 编码源有缓冲、非零起始 PTS 或可变帧率时，按实际画面帧和音频波形找触发点。每次移动画面要重查关联的对白、字幕、拟音、跨场底声和短 cue。成片片尾以确认后的画面安排为界；防止一条未裁的音频拖出额外黑尾。

一个语法例子如下。源片段 `a.mp4` 的第 1 秒才开始入画，画面在全片第 3 秒切到 `b.mp4`。单独的对白轨持续到第 3.375 秒，形成对白滞后的剪法。这个例子假定对白文件从源对白所需位置开始，实际工程要按波形对齐。

```html
<!doctype html>
<html lang="zh-Hans">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=1920, height=1080">
</head>
<body>
  <section>
    <video id="s01-a" src="assets/a.mp4#t=1,4" at="0" muted></video>
    <video id="s01-b" src="assets/b.mp4#t=2,6" at="3" muted></video>
  </section>
  <section>
    <audio id="dx-s01-a" src="assets/line-a.wav#t=0,3.375" at="0"></audio>
  </section>
  <section>
    <audio id="mx-01" src="assets/cue-01.wav#t=0,2.5" at="4"></audio>
  </section>
</body>
</html>
```

## 声音和画面的交接

借同轨首尾相接实现普通剪口。交叉淡化等确需重叠的画面放不同轨，并核对重叠区的层次、画面首尾和音频是否被重复。J-cut 可以让下一场声音提前，L-cut 可以让前一场声音越过画面剪口。用独立音轨安排具体源范围。有分离音频与原视频内嵌同一轨时，确认只播需要的版本。有口型对齐的部分，检查嘴、起音到停口实际都对得上，不随意对对白做变速。

支持的视频和音频增益、淡化或包络以当前官方手册及实际预览和渲染为准。需要音频渐变时，先用 Studio 可验证的功能；若当前工程没有可靠的时间变化增益，就将处理好的可追溯派生音频作为片段。视频 CSS 透明度和声音淡化要分别检验。截断混响前留出可用尾音，或有意把退乐交给清晰的声响。输出有分轨时留意对白、音效、音乐的静音与总轨替换，避免画面源音隐性出声。

自绘代码镜头由各自的页面以 `window.film.frame(t)` 定义画面，每个时间可以独立重画。避免依赖实际播放进度或上一帧留下的状态。声音摆在全片时间线。字幕优先采用当前版本能编辑和渲染的文轨；有配套 WebVTT 时按官方方式保留源时间。检查片段裁剪、变速、字幕提前和断句后，字幕是否仍在对应字词上，画面里的字与文轨有无重复。

## 审片版、锁定版与变更

至少能辨认供审片的版本和已被声音、字幕或交付采用的画面基准。时长尚在变化时，给试作标参考时间与关键事件。正式交接要记录 `film.html` 版本、画面参考、起算帧或时码、帧率、实际时长以及代理、临时特效或临时音乐。项目内有他人协作时，让他们用同一个参考版；单人短片在现有版本记录里标出基准即可。见 [[画面锁定让声音与交付共用一条时间线]]。

画面基准后获准再改，保留改前的可回看版本。按发生顺序记录每次插入、删除、等长替换或移位，标明片段 ID、旧范围、新范围和累计时移。对未被移动的镜内锚点，用事件复核；跨过插删的对白、拟音、环境声、字幕和音乐点需要按新时间回套。等长换镜也要核对嘴形、动作及音乐的真实落点。若有多个改段，在变更接点和更多轨道同时生效的位置查同步，再用同一新版导出并从头复看。记录方式见 [版本、素材和剪接](templates.md#版本素材和剪接)。

## 审片与导出

- 在 Studio 实际看画面，先连续审全片，必要时针对单个剪点逐帧回看。可用唯一片段 ID 或 `film.html#t=...` 把检查范围交给用户。
- `npx -y openfilm@latest look` 可做全片接触表与基本检查。`look 12.25` 看单帧，`look 12-14` 看一小段。画面测试需要的是剪口前后、动作末端、峰值与结尾的证据。接触表不能替代实时听看；变速、BGM 叠加、黑尾和渐变应在实际播放与成片文件中检查。
- 用户要求文件时，使用选定版本运行 `render`。按项目设定帧率、输出路径、清晰度及适用响度规格，先核对帮助。官方手册给出了适用于一般发布的响度预设，明确的发行规范优先。为测试风险高的声画接点或代码镜头可以做短段渲染。
- 终检使用导出文件本身核对时长、轨道、画幅、同步和片尾。版本提供 `look --full` 时可辅助识别意外黑场、闪帧、定住和跳帧，然后定位到实际输出。在导出路径不在默认位置或同目录有多个成片时，直接指定要检查的文件。用 `ffprobe` 或可信工具核对实际编码、分辨率、帧率和时长。播放器还要验证开头、场界、结尾与关键同步点确实正常。
- 失败时保留 OpenFilm 的真实输出，先定位到素材、时间线、浏览器或编码环节。修复后复跑受影响范围。未实际导出的项目交付为可编辑回看版本。文件能渲染、播放器能播、故事能被读懂是三项不同的验证。
