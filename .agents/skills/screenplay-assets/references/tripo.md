# Tripo CLI 执行与 credits 管理

本流程统一通过 Tripo CLI 执行，不使用自写 HTTP 或 SDK 绕过。先阅读 [官方 CLI 文档](https://developers.tripo3d.ai/en/docs/cli)，再核对本机 `tripo --help` 和相应子命令帮助；不要把 API 字段直接猜成 CLI 参数。本文于 2026-11-05 核对，实际参数以安装版本为准。

## 提交前准备

先确认 CLI 已安装并检查版本，缺失时说明安装需求。使用 `tripo doctor` 检查环境，沿用已有登录。需要登录时使用官方浏览器授权流程，不要求在聊天中提供 API key；账户区域必须由用户确认，不能根据语言推断。已有本地凭据不得打印或写入文档。

先检查已确认输入图是否清晰、完整、无遮挡，主体与背景是否分离，跨视图是否一致。人物尤其检查手臂与躯干、双腿是否可辨，衣物是否遮住关键关节；参考图不适于绑定时在提交前解决，而不是先付费碰运气。另制建模姿态图需要用户同意，并保留原确认版本。场景先判断单图能否合理表达所需空间；无法满足时说明限制，不以付费生成代替判断。

人物、场景和道具默认采用高模母版方案，预检时核对生成参数已省略 `face_limit`，并关闭云端自动减面。根据用途一次确定材质、纹理、输出格式及人物骨架需求，不默认开启最高质量或全部增值处理，也不为省单次费用而先生成注定要废弃的低质量试样。优先复用已有模型、贴图及任务结果。

先构建完整的 CLI 执行方案，使用当前版本支持的 `--dry-run` 预览；该能力不支持的子命令仅查帮助与文档，不能用真实提交替代预检。结合 `tripo balance`、当前定价及 dry-run 的可用估算，记录生成、绑定和必要转换的费用范围。估算不是实际扣费，余额也不是某项任务的成本。费用未知时明确说明，并在用户认可范围内才提交。

## 执行与恢复

使用 CLI 支持的本地图片输入生成模型，单图或多图方式遵从技能主流程；具体命令及输出目录参数先从本机帮助确认。图像输入必须是确认版本，不能用占位图。默认每项资产仅提交一次生成，不付费测试连接、不批量比较随机种子，也不先生成多个候选再挑选。

提交后立即记录任务 ID、输入版本、参数、CLI 版本和输出位置。按官方文档，已有任务可以通过 `tripo task watch <task-id> --download` 恢复等待和下载；先确认本机版本支持该语法。等待超时并不等于生成失败，网络错误也不证明任务未建立。结果不明时先检查原任务、CLI 记录、余额冻结及用量，禁止直接重提。避免在外层循环自动重跑生成命令。

人物模型成功后使用 CLI 支持的绑定兼容检查与骨骼绑定能力，先核对相关帮助及计费。必要绑定属于预先列明的任务链，不是重复生成；不额外附带用户未要求的动画。若 CLI 不支持所需步骤，明确报告限制，不擅自切到直接 API。绑定失败时保留原模型，先定位原因，不能重跑整个生成链。

任何额外付费重做之前，说明失败的具体原因、准备修改的输入或参数、为何现有结果无法修复，以及新增费用，获得用户同意后再执行。没有新的有效改进依据时停止重复尝试。可离线完成的检查与修复优先离线完成。

## 保存与验收

文件保存或复制到 `Assets/Models3D/` 对应资产目录，保留原始模型和绑定模型，检查文件有效、材质完整。人物检查骨架、蒙皮及肩肘膝简单变形；没有检查条件时写“已绑定，待检查”，不能将静态模型登记为绑定完成。骨骼绑定不自动包含面部表情控制器。场景检查布局与尺度，道具检查轮廓和材质。

从 `tripo usage` 或任务结果取得实际消耗，记录到统筹表；没有返回费用时标明未知，不拿余额差值冒充单项费用。保存脱敏任务记录及输入版本，不能只留临时下载链接。本技能维护或验证时不提交真实生成任务，不消耗用户 credits。
